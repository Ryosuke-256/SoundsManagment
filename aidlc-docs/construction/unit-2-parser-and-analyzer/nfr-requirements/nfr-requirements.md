# Unit 2 NFR Requirements: Metadata Parser & Audio Signal Analyzer

## 1. Performance Requirements

| 項目 | 目標値 | 検証方法 |
|---|---|---|
| ファイル名パース速度 | 1,000件あたり < 50ms（1件あたり < 0.05ms） | ベンチマークテスト（1,000件の正規表現抽出） |
| DSP音声解析速度 (BPM/Key) | 1ファイル（先頭15秒）あたり < 150ms | 100件のサンプル音声バッチ解析時間計測 |
| 自動リネーム・整形速度 | 100件あたり < 20ms | 文字列置換およびパス生成ベンチマーク |

---

## 2. Resource & Memory Requirements

| 項目 | 要件仕様 |
|---|---|
| メモリ消費上限 | 1ファイル解析時のピークRAM使用量 < 10MB |
| 音声読み込み制限 | 長尺音声であっても先頭最大 15〜30 秒間のみをロードし、長大な音声によるメモリ枯渇を防止 |
| CPU使用率制御 | バッチ解析時、UIスレッドをブロックしないバックグラウンドワーカー動作 |

---

## 3. Reliability & Fault Tolerance Requirements (RESILIENCY-10)

| 項目 | 要件仕様 |
|---|---|
| 破損ファイル耐障害性 | ゼロバイト、フォーマット異常、壊れたヘッダを持つファイルに遭遇しても例外を分離トラップ |
| バッチ継続性 | 解析失敗したファイルのみエラーログを記録し、メタデータに「Other」を設定して全体のインポート処理を継続 |
| 入力文字列堅牢性 | 空文字、制御文字、不正Unicode、超長文字列ファイル名が渡されてもパーサーがクラッシュしない |

---

## 4. Testability Requirements (PBT)

| 項目 | 要件仕様 |
|---|---|
| Property-Based Testing | Hypothesisフレームワークを用い、ランダムな文字列入力に対する不変条件（クラッシュなし、BPM範囲整合性、Key表記整合性、Type収束）を網羅検証 |
