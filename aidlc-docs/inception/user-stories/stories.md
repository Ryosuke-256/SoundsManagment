# User Stories: Sound Sample Manager (音源管理ソフト)

## Overview
本ドキュメントでは、音源管理ソフトのユーザーストーリーを定義します。
ユーザーの要望に基づき、システムは以下の2大メインピラー（柱）を中心に構成されています。

1. **メインピラー 1: 音楽制作ワークフロー（音源検索・プレビュー試聴・DAW連携）**
2. **メインピラー 2: 音源ライブラリ & データベース管理（インポート・自動整理・「Other」管理・DB同期）**

すべてのストーリーは **INVEST基準** に準拠し、受入基準（Acceptance Criteria）はチェックリスト形式で定義されています。

---

# 🎵 メインピラー 1: 音楽制作ワークフロー

## Story 1.1: 多角的なファセット絞り込みとソートによる音源検索
- **As a**: アレンジャー / 作曲家（ユウキ）
- **I want to**: タイプ（Loop/Oneshot/Other）、楽器種別、ジャンル/パック、BPM範囲、キー（調性）、制作者を自由に組み合わせて音源リストを絞り込み・ソートしたい
- **So that**: 制作中の楽曲のテンポやキーに合致する最適な音源を数秒で見つけ出し、制作の中断を防ぐことができる

### Acceptance Criteria (チェックリスト)
- [ ] 左サイドパネルに「Type（Loop / Oneshot / Other）」の切り替えボタン/チェックボックスが表示され、選択時に即座に一覧が絞り込まれること
- [ ] 楽器（Bass, Guitar, Synth, Kick, Clap, Drums, Beats, Other 等）のファセットタグを選択して絞り込みができること
- [ ] BPMスライダーまたは最小・最大入力欄でテンポ範囲（例: 170〜178 BPM）を指定して絞り込めること
- [ ] キー選択（C, C#, D, D#, E, F, F#, G, G#, A, A#, B × Major/Minor）で該当する調性の音源のみ表示できること
- [ ] 上部検索バーにフリーワード（例: "dist", "808", "heavee"）を入力すると、リアルタイムにインクリメンタル検索されること
- [ ] 音源テーブルの各カラムヘッダー（ファイル名、BPM、Key、楽器、Type等）をクリックすることで昇順・降順ソートができること
- [ ] 絞り込み条件のリセットボタンを押すと、全音源表示状態に瞬時に戻ること

---

## Story 1.2: 波形表示と自動再生・ループ試聴による高速プレビュー
- **As a**: 音楽クリエイター（ユウキ、ケンタ）
- **I want to**: リスト内の音源を選択した際に波形（Waveform）が表示され、自動再生やループ再生で即座に試聴したい
- **So that**: DAWに配置する前に、音色の質感やフレーズのノリを素早く直感的に確認できる

### Acceptance Criteria (チェックリスト)
- [ ] 音源リストでアイテムを選択（矢印キー移動またはマウスクリック）した際、遅延50ms未満でプレビュー再生が開始されること（Auto-Play ON時）
- [ ] 「Auto-Play（自動再生）」トグルボタンがあり、OFFのときは選択しても自動再生されず、再生ボタンを押した時のみ再生されること
- [ ] 下部プレビューバーに音源の波形（Waveform）がグラフィカルに描画されること
- [ ] 波形上に現在の再生位置を示すシークバー/再生ヘッドが表示され、波形上をクリックするとその位置へジャンプ再生できること
- [ ] 「Loop Playback（ループ再生）」トグルボタンがあり、ONのときは音源終端に達した際に先頭からシームレスに繰り返し再生されること
- [ ] 再生（Play）、一時停止（Pause）、停止（Stop）、およびマスター音量スライダーが正常に動作すること

---

## Story 1.3: DAW（Cakewalk / Sonar等）への直接ドラッグ＆ドロップ連携
- **As a**: DAWユーザー（ユウキ）
- **I want to**: アプリ内の音源リストから目的のファイルを直接Cakewalk by BandLabやSonarのトラックへマウスでドラッグ＆ドロップして配置したい
- **So that**: エクスプローラーを手作業で開く手間を省き、シームレスにDAWタイムラインへ素材を組み込める

### Acceptance Criteria (チェックリスト)
- [ ] 音源リストのアイテムをマウス左ボタンドラッグした際、OS標準のファイルドロップ（`text/uri-list` / ファイルパス）が開始されること
- [ ] Cakewalk by BandLabおよびSonarのオーディオトラックまたはトラックビューへドロップした際、正常にオーディオクリップとして配置されること
- [ ] Windowsエクスプローラーやデスクトップへのドラッグ＆ドロップでもファイルコピー/移動が機能すること
- [ ] アイテムの右クリックメニューに「エクスプローラーで表示」「ファイルパスをクリップボードにコピー」のアクションがあり、実行時に該当フォルダが開く/パスが取得できること

# 🗄️ メインピラー 2: 音源ライブラリ & データベース管理

## Story 2.1: 音源のインポートと自動フォルダ整理 & 「Other」フォールバック
- **As a**: サウンドコレクター / トラックメイカー（ケンタ）
- **I want to**: ダウンロードした音源フォルダ（例: `Loop/`, `Oneshot/`）をアプリに読み込ませた際、ファイル名からメタデータを解析して管理ライブラリフォルダへ自動分類配置し、判別不能な音源は「Other」フォルダへ安全に振り分けたい
- **So that**: 散らかった音源を手間なく構造化し、未分類の音源も漏れなく管理できる

### Acceptance Criteria (チェックリスト)
- [ ] 「フォルダをインポート」ボタンから任意のディレクトリを選択してインポート処理を実行できること
- [ ] ファイル名規則（例: `03_SS_Guitar_Snob_174_4_bar_Loop_C#_guitar_174BPM_C♯minor_BANDLAB.wav`）を解析し、Type, BPM (174), Key (C# minor), Instrument (guitar), Pack (SS_Guitar_Snob), Creator (BANDLAB) を自動抽出できること
- [ ] 解析結果に基づき、管理フォルダ構造（`Library/Loop/[Genre]/[Instrument]/` 等）へファイルを整理・コピー配置できること
- [ ] 楽器名やジャンル名、Typeが特定できなかったファイルは、自動的に `Library/Loop/Other/` や `Library/Oneshot/Other/`、`Library/Other/` 等の「Other」サブディレクトリへ配置され、タグにも「Other」が付与されること
- [ ] インポートの進捗状況がプログレスバーで表示され、処理完了時にインポート件数（成功件数、Other分類件数）がサマリー表示されること

---

## Story 2.2: 「Other」分類音源の確認と手動メタデータ編集・カスタムタグ付け
- **As a**: ライブラリ管理者（ケンタ）
- **I want to**: 「Other」タグで絞り込んだ音源を試聴しながら、正しい楽器名やキー、カスタムタグを手動で編集・付与したい
- **So that**: 自動解析で拾えなかった音源を完璧に整理し、将来の検索性を高めることができる

### Acceptance Criteria (チェックリスト)
- [ ] ファセットフィルターで「Other」を選択することで、未分類属性を持つ音源のみを瞬時にリストアップできること
- [ ] リスト上で音源を選択し、詳細パネルまたは右クリックメニューから「メタデータ編集」を開けること
- [ ] Type, BPM, Key, Instrument, Genre, Creator, カスタムタグ（例: "Favorite", "Dark", "Punchy"）を編集・保存できること
- [ ] 複数ファイルを選択して一括で同一のタグ（例: 一括で Instrument="Bass" や Genre="Trap"）を付与できること
- [ ] 編集内容がSQLiteデータベースおよび内部インデックスに即座に反映され、リストの表示が更新されること

---

## Story 2.3: データベースの永続化・高速検索同期・自動バックアップ
- **As a**: 全てのユーザー（ケンタ、ユウキ）
- **I want to**: 数万件の音源メタデータがSQLiteデータベースに安全に保存され、アプリ起動時に即座に利用可能で、定期的に自動バックアップされること
- **So that**: アプリが高速に起動・検索でき、不慮のクラッシュやPC停止でもライブラリデータが失われない

### Acceptance Criteria (チェックリスト)
- [ ] メタデータがローカルSQLiteデータベース（`SoundLibrary/Database/library.db`）に保存されること
- [ ] SQLiteのWAL（Write-Ahead Logging）モードが有効化され、高速な読み書きと破損耐性が確保されていること
- [ ] アプリ起動時およびシャットダウン時にDBの整合性チェック（Integrity Check）および自動バックアップ（`SoundLibrary/Backups/` に直近5世代）が実行されること
- [ ] 壊れたWAVファイルや無効なオーディオファイルが検出された場合でも、アプリがクラッシュせずスキップしてログ出力されること（RESILIENCY-10）
- [ ] アプリ再起動後、前回インポートしたすべての音源とタグ情報が瞬時にロードされること

## Story 2.4: 不明音源の定量音声解析（BPM/キー自動算出）と命名規則リネーム
- **As a**: サウンドコレクター / トラックメイカー（ケンタ）
- **I want to**: BPMやキー情報が欠落している音源（「Other」分類等）に対し、音声解析エンジンを実行してBPM（テンポ）とキー（調性）を自動算出し、標準命名規則に沿ってファイル名へ付け足す（リネーム）機能を利用したい
- **So that**: 散乱した出所不明のサンプルでも自動的に定量データが付与され、ファイル名だけで判別可能になると同時に、検索・制作ワークフローや管理ライブラリに統合できる

### Acceptance Criteria (チェックリスト)
- [ ] 「音声解析・自動リネーム」機能（ツールバーまたはリスト上の右クリックメニュー）から、選択した音源または「Other」分類音源のバッチ解析を実行できること
- [ ] 音声波形・オンセット解析（Onset/Tempo検出）により、音源のBPMを自動算出できること（例: 174 BPM）
- [ ] クロマ特徴量・ピッチクラス解析により、音源の主調（Key, 例: `C#m` / `C# minor`, `Dm` / `D minor`）を自動推定できること
- [ ] 解析完了後、検出されたBPM・キーおよび新しいファイル名候補（例: `Bass_01.wav` → `Bass_01_174BPM_Dminor.wav`）をダイアログ等でプレビュー確認できること
- [ ] ユーザーが「適用」を実行すると、実ファイルが命名規則に沿ってリネームされ、管理フォルダ内の適切なサブフォルダ（例: `Library/Loop/[Genre]/[Instrument]/`）へ再配置・移動されること
- [ ] SQLiteデータベース上のメタデータ（BPM, Key, ファイルパス）が更新され、「Other」分類から正規属性へ自動昇格すること
